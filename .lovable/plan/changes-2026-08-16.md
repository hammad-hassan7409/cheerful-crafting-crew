Implement a numeric Pin Order system for products to replace the current boolean pinning mechanism. This will allow the admin to manually set the display order of pinned products on the homepage.

## Changes

### Schema and Functions

- Update `productSchema` in `src/lib/products-admin.functions.ts` to reflect the new pin logic (allowing `pin_order` to be nullable or 0-indexed effectively).

### Database Logic

- Add a new server function `updatePinOrder` to handle the automatic reordering of existing pinned products when a new priority is assigned, ensuring no duplicates.

### Admin Panel

- **Admin Dashboard (`src/routes/admin/index.tsx`):**
  - Replace the Pin/Unpin toggle with a "Pin Order" numeric input.
  - Implement the `updatePinOrder` logic to handle changes directly from the dashboard.
- **Product Form (`src/routes/admin/products.$productId.tsx`):**
  - Update the UI to focus on "Pin Order" instead of a boolean toggle.
  - Ensure saving a product with a new Pin Order triggers the reordering logic.

### Homepage

- **Home View (`src/routes/index.tsx`):**
  - Refine the product sorting logic to ensure pinned products (those with a non-null/non-zero `pin_order`) appear first, sorted by `pin_order`, followed by unpinned products in their original order.

## Technical Details

### Reordering Logic

When a product is assigned a Pin Order $P$:

1. If $P$ is already taken by another product $A$, increment $A$'s Pin Order and recursively check for duplicates.
2. If a Pin Order is cleared (set to 0 or null), shift subsequent pinned products down to fill the gap.
3. Treat `is_pinned` as a helper column (or rely solely on `pin_order > 0`).

### Home Sorting

```sql
ORDER BY 
  CASE WHEN pin_order > 0 THEN 0 ELSE 1 END,
  pin_order ASC,
  created_at DESC
```

### Constraints

- No changes to UI/design outside the admin pin options.
- No modifications to video playback, storage, or pricing logic.
- Preserve existing product ordering for unpinned items.     
“For unpinned products, do not introduce `created_at DESC` sorting unless that is already the existing homepage ordering. Preserve the exact existing unpinned product order.”
